# Backend — Node + Postgres (production scale)

The dashboard runs in **two modes** with the **same frontend and the same API shape**:

| Mode | When | Where data lives |
|---|---|---|
| **Local (demo)** | `DATABASE_URL` unset | `src/data/manifest.json` + `src/data/batches/*.json` (generated by `generate_convin_data.py`) |
| **Postgres (production)** | `DATABASE_URL` set | Postgres: `account_rows` (raw) + `batches` (computed payload) |

The switch is automatic — `src/lib/db.mjs` imports `pg` **lazily**, so local mode needs no
database and no `pg` install. This is what keeps the boardroom demo un-killable while the
scale path sits behind the same UI.

## How it scales to ~1M rows/day
- Raw rows live in **Postgres**, not in the browser. The Account Explorer calls **`/api/rows`**
  with server-side pagination, filtering and sorting (indexed) — the browser only ever holds one page.
- Every section/KPI/intelligence value is **pre-computed once per upload** in a single streaming
  pass (`src/lib/aggregate.mjs`) and stored as a small JSON payload in `batches.payload`. The
  dashboard reads that payload — tiny regardless of row count.
- Each upload is a **batch**; a merged **Day Total** is recomputed per date. Multiple uploads on
  a day appear as tabs; the date stepper moves between days.

## Files
- `db/postgres/schema.sql` — tables + indexes (+ note on partitioning for very high retention).
- `src/lib/csv.mjs` · `normalize.mjs` · `aggregate.mjs` — parse → canonical rows → payload (dependency-free; unit-tested against the real CSV).
- `src/lib/db.mjs` — Postgres access (lazy `pg`).
- `src/lib/ingest.mjs` — normalize + insert + payload + Day-Total recompute.
- `src/lib/backend.mjs` — read facade used by the API routes (Postgres or local fallback).
- API routes: `GET /api/data` (manifest) · `GET /api/batch?id=` (payload) · `GET /api/rows?…` (paged rows) · `POST /api/ingest` (upload).
- `migrate.mjs` (`npm run db:setup`) · `ingest.mjs` (`npm run ingest`).

## Setup (local Postgres)
```bash
docker compose up -d                                   # starts Postgres on :5432
export DATABASE_URL=postgres://rbl:rbl@localhost:5432/rbl
export PGSSL=disable                                   # local docker has no SSL
npm install                                            # installs pg
npm run db:setup                                       # applies schema
node ingest.mjs "src/data/convin_source.csv" 2026-07-07 1   # load a day's file (slot 1)
npm run dev                                            # dashboard now reads Postgres
```
Upload more files for the same day as slot 2, 3 … → they show up as tabs, with a merged Day Total.

## Deploy (Vercel + GitHub + managed Postgres)
1. Create a Postgres on **Supabase** or **Neon**; copy its connection string.
2. In Vercel project env vars set: `DATABASE_URL`, `DASHBOARD_PASSWORD` (leave `PGSSL` unset — managed Postgres uses SSL).
3. Push to GitHub → import in Vercel (Next.js auto-detected). Run `npm run db:setup` once against the DB.
4. Load data via `POST /api/ingest` (multipart `file`, optional `report_date`, `slot`) or the CLI.
   For very large single files, prefer the CLI (`node --max-old-space-size=4096 ingest.mjs …`) or split per day.

## Alternate max-scale path
`backend/` contains a ClickHouse schema + Go-ingester stub — the tens-of-millions/day option.
It is **not used** by default; the active production backend is Node + Postgres described here.
